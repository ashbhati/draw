# Workspace storage API (V2 foundation)

Draw stores workspaces and boards locally in IndexedDB. A workspace represents one project and contains exactly one board; each board points to one editable `DrawDocument`. A board is not a `.draw` file: the portable file remains a self-contained format v1 document and can be moved independently.

## Migration and compatibility

The database moves through schema version 11. During upgrade, the former `documents["current"]` record is copied under its existing `document.id`, attached to a default workspace and board, and selected as active. Its portable document content, assets, scene/view revisions, app state and viewport are preserved. Malformed legacy content is quarantined and reported as a `DrawStorageRecoveryError`; it does not abort that migration. Data created by the earlier V5 draft is re-keyed. Schema 11 splits any older multi-board workspace into one workspace per board while preserving each board ID, document ID/content/revisions, and document undo/redo history. The original workspace keeps its oldest board; other boards move to newly named workspaces, each receiving a copy of the original library items and assets without library operation receipts. The active pointer follows its board. Old workspace operation receipts are cleared and the catalog revision advances, so an old catalog retry conflicts instead of replaying obsolete workspace relationships. If a library needed for copying is malformed, the versionchange transaction aborts as a whole; the original database version and rows remain available for repair and retry.

The old `current` row remains only as a compatibility alias for V1 clients; namespaced IndexedDB keys protect it from arbitrary document IDs. Existing MCP operation history remains keyed by the same document ID. Schema 7 added the workspace receipt store and catalog revision metadata; schema 8 compacts receipts into operation IDs/revisions, migrates away historical document snapshots, and prunes to 30 days and 1,000 entries. Schema 9 adds workspace-scoped reusable library data with per-library revision and idempotency receipts.

Library receipts retain only idempotency metadata and compact result fields (item ID/name, flags, and library revision); they never retain element arrays or embedded image data. Each library record keeps at most 256 receipts from the preceding 90 days. A delete_workspace MCP transaction removes the workspace library row together with its workspace and canvas records. Same-key retries continue to return the compact committed result, including after the associated item is deleted.

Fresh installs create their default workspace and first board on the first document save. `createWorkspace(name)` creates a workspace and blank board atomically; `createWorkspaceWithCanvas(name, boardName, source?)` creates a workspace and board together, optionally importing a source document with a new document ID and reset local revision counters. Import copies the scene and embedded assets, so it behaves as “open as new” and never overwrites the source document. `createCanvas(workspaceId, ...)` only populates a legacy or otherwise empty workspace and rejects if it already has a board. `duplicateCanvas` creates a separate workspace and copies the source board, embedded assets and library items.

## API

`listWorkspaces()` and `listCanvases(workspaceId)` return metadata in creation order; after migration every workspace has one board. `createWorkspace(name)` returns the workspace after atomically creating its blank board; use `createWorkspaceWithCanvas(name, boardName, source?)` to create a board from an imported `.draw` document in one transaction. `createCanvas(workspaceId, name, source?)` only populates a legacy or otherwise empty workspace. `loadCanvasDocument(canvasId)` loads a board without changing the active selection. `setActiveCanvas(canvasId)` selects a board and its workspace for the editor shell. `deleteCanvas(canvasId)` is unsupported because removing the sole board also removes its workspace library and history; use the approved `deleteWorkspace(workspaceId)` flow, whose confirmation covers the entire project. `saveCurrentDocument(document)` persists only when the document is still selected, so an autosave scheduled before a workspace switch cannot overwrite or activate another board. Pass `{ replaceDocument: true }` only for an explicit open/replace operation in the currently selected board. Replace keeps the board ID, assigns the imported document a fresh ID, advances its scene and view revisions beyond the previous document, and removes the replaced document's private undo/redo and operation history. The returned `document` is the normalized document that the editor and MCP clients must adopt.

On load, a missing or dangling active pointer is repaired to the first intact board. If board records exist but none has a valid document, or a quarantined legacy document needs recovery, storage raises `DrawStorageRecoveryError`. A missing board document is not treated as a new empty drawing. If every workspace was intentionally deleted, new autosaves do not silently recreate a deleted board.

These functions are exported from `src/ui/storage.ts`. The editor UI and MCP tools use these APIs. MCP `create_canvas`, `duplicate_canvas`, and `.draw` import create a new workspace with one board; the source workspace library items are copied where applicable. `rename_canvas` renames the board and its document title; `select_canvas` selects its owning workspace. MCP `delete_canvas` is rejected before asking for human approval; callers should inspect `list_workspaces` and use the one-use approved `delete_workspace` operation, which removes the project, library, drawing, and history together. MCP mutations run through the authenticated active editor and commit their workspace/document change and idempotency receipt in one IndexedDB transaction. Exact retries rebuild the response from current catalog/document storage, never a stale snapshot; a reused key with a different payload conflicts. `.draw` import through MCP creates a new workspace/board/document and preserves the source and existing workspaces. Deletes remove compact receipts that refer to the deleted workspace/board in the same transaction.

## Failure behavior

Workspace/canvas operations use IndexedDB transactions. A failure while creating a canvas aborts both the canvas row and the newly copied document. Draw file export remains independent of this local database: `.draw` retains editable scene data/assets; PNG/JPEG remain flattened shareable images.
