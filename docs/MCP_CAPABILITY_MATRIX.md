# Draw MCP capability matrix

This document translates the V2 goal—agents should be able to do the meaningful work available to a person in Draw—into a reviewable capability and safety contract. The target is **semantic capability parity**, not a remote imitation of every mouse gesture: an agent requests an operation such as “create a labeled box”, while the editor remains responsible for rendering, hit testing, and canvas interaction.

Status labels below are deliberate: **Available (V1)** describes implemented behavior; **Unsupported (V1)** means no current MCP operation exists; **Proposed (V2)** is a design target, not an implementation claim. Tool names and detailed schemas are proposals for issue #31 review.

## Current MCP contract (V1)

| Tool | Input currently accepted | Output currently returned | Important limits |
| --- | --- | --- | --- |
| `get_current_canvas` | Optional `offset` (default 0, max 1,000,000) and `limit` (default 250, max 250). | `id` (the document ID; not `documentId`), `title`, background preset, viewport, total element count, page metadata, and elements with IDs, types, text excerpts, geometry, container/bound links, and colors. | Flushes the active tab first. It is paginated, but has no snapshot/revision token. The response's `id` field should be renamed or aliased to `documentId` in a versioned V2 contract. |
| `create_diagram` | Optional title; 1–100 nodes, each requiring caller `id`, non-empty `label`, finite x/y; optional dimensions, shape (rectangle/ellipse/diamond), color; up to 200 edges (`from`/`to`, optional label/color). | Maps caller node IDs to Draw IDs in `nodes`; maps node label IDs in `nodeLabels`; returns created edges with element IDs and optional label IDs, `addedElementIds`, and optional `titleElementId`. | Node labels are required in V1; edge labels are optional. Creates native editable Draw/Excalidraw elements, not a raster image. |
| `update_elements` | 1–100 updates by element ID. Patch fields: non-empty text, x/y, width/height, strokeColor, backgroundColor. | Updated element IDs and result/warning data. | Cannot create standalone text, lines, freehand, or image elements; no delete, duplicate, group, reorder, selection, background, document lifecycle, export, undo, or redo tools. |

The development bridge currently accepts only loopback requests, checks the request Host against the configured loopback host/port, rejects a mismatched Origin when Origin is present, and requires JSON for mutation requests. The bridge's request-body ceiling is 100 MiB. The MCP process has a 25-second HTTP request timeout; the Vite bridge's default command timeout is 20 seconds, and late acknowledgements are retained for 60 seconds. The bridge assigns an in-memory `draw-command-…` ID and client ID; it has no caller idempotency key, persistent operation ledger, or document revision today. A command can already have applied when the caller receives a timeout; V1 instructs the client to call `get_current_canvas` before retrying. If a scene mutation applies but local autosave or bridge sync fails, V1's persistence helper retains the applied scene and returns an applied-but-not-confirmed-saved warning with recovery guidance; it does not roll back the scene or reduce the result to a bare error.

## V2 phases

These phases are a proposed order, not a release commitment. They keep file safety and protocol decisions ahead of broad tool implementation.

1. **Phase 0 — Contract and threat boundaries (#31):** approve the matrix, schemas, revision/idempotency ownership, undo policy, local-file permissions, and open/switch/overwrite confirmations.
2. **Phase 1 — Native authoring (#32):** create core Draw elements and relationships through MCP; verify an agent-created file opens and a human can edit it.
3. **Phase 2 — Scene editing and document lifecycle (#33):** edit/arrange/history, background/viewport, read/save/open/export; preserve editable `.draw` state and protect concurrent human edits.
4. **Phase 3 — Workspaces (#34):** migrate the existing single local document into project organization without data loss.
5. **Phase 4 — External image search (#35):** search, inspect rights metadata, then embed the chosen image and its attribution. Reusable local library additions remain tracked separately in #11.
6. **Cross-cutting packaging (#28):** production MCP runtime and end-user install path are prerequisites for a distributable release, rather than a prerequisite for local development work.

## Identifier, revision, and pagination proposal

- `documentId` is the stable identity of one Draw document. The current V1 summary returns it under the field name `id`; V2 should expose `documentId` and may keep `id` as a deprecated alias for compatibility. It is distinct from workspace/canvas display names.
- Every scene object has a Draw-generated stable `elementId`. Caller-supplied node keys are request-local aliases only; responses map them to persistent Draw IDs. IDs are scoped to one document.
- V2 responses include two monotonically increasing revisions owned by the Draw application/document store, not by the stdio MCP process or Vite bridge: `documentRevision` for scene/content/layout, and `viewRevision` for viewport. Both are persisted in local autosave and `.draw` metadata. V1 documents migrate to initial revisions (for example 0/0); document identity changes start a new revision namespace.
- Element creation/update/delete/arrangement, text, assets, title, and background increment `documentRevision`. A human pan/zoom or MCP viewport/fit operation increments `viewRevision` only, so ordinary navigation does not invalidate an agent's scene edit. Transient selection/focus increments neither. Scene undo/redo increments `documentRevision`; viewport-only history, if provided, increments `viewRevision` only. Revisions never move backward.
- Human viewport gestures are coalesced: pan/zoom events update transient view state, then increment and persist `viewRevision` once when the gesture settles (proposed 250 ms debounce after the final input). Explicit MCP viewport/fit operations commit once when complete. A page hide/reload flushes the final settled view where possible; intermediate pointer/wheel events do not each create a revision.
- Every mutation input includes `documentId`; scene mutations include `expectedDocumentRevision`, and viewport mutations include `expectedViewRevision`. The named document must be authorized for the caller and active/writable for the current tool operation; a mismatch returns a conflict without changing another document.
- One active writer owns a document. Preserve V1's writer lock/read-only tab behavior until V2 has a tested conflict-resolution model. Tab `clientId` is an ephemeral routing identity and may change on reload; it is not the durable identity used for idempotency. On reload Draw restores the persisted `documentRevision` and `viewRevision`; stale in-flight acknowledgements from the prior tab client are rejected.
- `get_current_canvas` returns `documentId`, both revisions, and a cursor pinned to `documentRevision` (not `viewRevision`). Viewport changes do not invalidate scene pages. If scene revision changed, return a conflict and require a fresh first-page read; do not silently shift offsets. Cursor data is derived from document ID/revision/offset or backed by an equivalent immutable snapshot, so it remains valid across reload when the same scene revision is still available.
- Each MCP installation is paired through the human-approved bootstrap in the Local bridge threat model and receives a stable random `clientIdentity`, persisted by Draw's MCP configuration/local settings and supplied by the MCP client on every call. This survives browser/tab reloads and MCP subprocess restarts; it is separate from the ephemeral tab `clientId` used to route to the active editor.
- Every mutation input includes `documentId`, `clientIdentity`, `idempotencyKey`, and the relevant expected revision. Draw computes a canonical hash of the fully validated operation payload, including `documentId`. The ledger key is `(documentId, clientIdentity, idempotencyKey)`. Retain completed operation records for **7 days** from completion in Draw's durable local application store. A replay during that window with the same key and same hash returns the original `operationId`/result; reuse with a different payload returns `IDEMPOTENCY_KEY_REUSE` and never applies the new payload. Authenticate the caller before returning a replay, then check a valid caller's idempotency record before its current revision.
- Document changes and their operation-ledger entries survive a process restart only when atomically committed together. A stdio server may cache results but is not authoritative. If the committed record is older than 7 days, return `OUTCOME_UNKNOWN` with `reason: idempotency_expired`; read the current canvas, reconcile explicitly, and use a new key for any subsequent mutation. Never silently reapply an expired operation.
- The current V1 bridge state (`document`, active client, command sequence, pending acknowledgements) is in memory. Its generated command IDs are unique only within the live bridge lifetime. The 20-second bridge command timeout and 60-second late-ack retention do not constitute durable operation history; MCP's HTTP wrapper times out at 25 seconds. V2 should replace this with revision/idempotency semantics while retaining a recovery/read-after-timeout path.

## Mutation and undo/redo semantics proposal

- Validate the full batch before applying. Prefer atomic all-or-nothing behavior; if any operation supports partial results, return explicit per-element statuses and the resulting revision.
- A successful logical MCP scene mutation is one history transaction. Record its `operationId` and actor (`human` or stable MCP `clientIdentity`) in local document history. Viewport-only changes are not scene history transactions. Mutation responses include `applied` (whether the scene change took effect in the running editor), `persisted` (whether the resulting revision and operation result reached durable Draw storage), and `persistenceWarning` (stable code/message or `null`). If applied but not persisted, return `applied: true`, `persisted: false`, and a warning that the change is present only in the running editor and may be lost on restart; do not roll it back or claim durable completion. Keep an in-memory operation journal while the process remains alive so same-key retries return the original result without reapplying. This in-memory journal does not survive restart. After restart without an atomically committed document+ledger record, return `OUTCOME_UNKNOWN` with `reason: process_restarted`; durability and idempotent replay are guaranteed only when the scene revision and operation result were atomically committed.
- `undo_operation(operationId)` only reverses that MCP actor's latest still-eligible scene operation. If any human/other-client scene change followed it, return `CONFLICT` without changing the canvas. A later viewport-only `viewRevision` change does not block scene undo. This avoids a delayed agent undo from reverting later human work. If finer-grained inverse application is added later, it must detect dependencies and preserve subsequent human edits.
- A human keyboard Undo may undo the latest scene operation from any actor, including an MCP mutation. Every successful scene undo/redo is itself a new persisted state and increments `documentRevision`; it never decrements or reuses a prior revision. If an app later adds undoable viewport history, that action increments `viewRevision` only.
- Redo is bound to the operation just undone and its resulting `documentRevision`. A newer scene edit clears or conflicts the redo target; a pan/zoom does not. Never replay stale state over new work.
- Timed-out mutations are resolved by querying operation status by `documentId` + `clientIdentity` + `idempotencyKey` or re-reading the canvas. While the original process is alive, same-key/same-payload retry consults its in-memory journal and returns the original applied/persisted/warning outcome without reapplying. After restart, if no durable operation record exists, return `OUTCOME_UNKNOWN` with `reason: process_restarted`: read the current document, compare the intended change, and require explicit caller/user reconciliation followed by a new idempotency key before another mutation. If a durable record expired after seven days, return `OUTCOME_UNKNOWN` with `reason: idempotency_expired` instead. Never blindly retry an unknown create. A timeout does not imply the scene change failed.

## File and local-data safety proposal

The installed MCP runtime remains local-first and loopback-bound, per #28. An MCP stdio subprocess does not, by itself, grant permission to access arbitrary filesystem paths.

- Default tools operate on the document named by `documentId`. `open_document` may read a relative path only inside the canonical, user-configured Draw directory, or accept a client-provided artifact/resource reference. It cannot read an arbitrary absolute path; the MCP client cannot grant itself a new root.
- A user may explicitly configure one local Draw directory for MCP file operations. Canonicalize the configured root and candidate parent, resolve symlinks, and reject path traversal or any target that resolves outside the root. Do not follow target symlinks or allow symlinked path components.
- Inputs validate actual file content, not trust the filename or MIME claim. `.draw` bytes must parse as a supported Draw format and match the `.draw` extension when a path is used. The maximum `.draw` size is 100 MiB of **decoded raw file bytes**. Do not send large document bytes through model context: use an MCP artifact/resource or approved local path by default. Proposed inline arguments cap at 1 MiB decoded raw content; ordered transfer chunks cap at 1 MiB decoded raw bytes each. Separately cap each encoded JSON/MCP chunk envelope at 2 MiB and each complete JSON command envelope at 4 MiB, including metadata/base64 expansion. If image support is later specified, cap each decoded raw image at 20 MiB and enforce decoded pixel dimensions; #32 does not accept images. Verify decoded byte counts and SHA-256 before parsing/commit.
- Output extensions are restricted to `.draw`, `.png`, `.jpg`, or `.jpeg` and must case-insensitively match the requested output type. Normalize names to Unicode NFC. Draw serializes its own writes under a per-canonical-directory lock and checks case-folded names before commit. This reduces collisions among Draw operations; on a case-sensitive filesystem, the case-fold scan is best-effort against non-Draw writers and cannot guarantee uniqueness if another process races in a differently cased name. For exact target collisions, write and flush a temporary file in the same approved directory, then commit a new file with an OS-supported atomic no-replace primitive. If the exact target appears or a detected case-folded collision exists, return `PATH_EXISTS` with no partial final file; fail closed if atomic no-replace is unavailable.
- Save to a new, non-existing path is allowed inside the configured root via the no-replace atomic write above. When open would replace unsaved active state or save targets an existing path, Draw returns `NEEDS_CONFIRMATION` with a random one-use token, action, expected revisions, canonical path, and expiry (proposed: two minutes) without opening/overwriting the file. Draw's UI presents the prompt; the MCP caller cannot approve it.
- A human confirmation result is one of `approved`, `denied`, or `expired`. The token is bound to `clientIdentity`, `documentId`, action, target, revision, and—when overwriting—file identity/hash. It cannot be reused. On approval, Draw resumes the operation after re-resolving the path and checking that the document/target has not changed; otherwise it returns `stale` and requires a new prompt. A denied or expired token performs no operation.
- Opening a document that would discard unsaved active state similarly requires the UI confirmation above. A normal project/canvas switch preserves both documents and does not need destructive replacement. No MCP flag or model-provided string bypasses confirmation.
- For an approved overwrite, hold the per-directory serialization lock and a per-path lock, recheck the target identity/hash, then use an atomic conditional replacement. If the OS/filesystem cannot guarantee the target is still the confirmed file at replacement time, stop with `stale` and require the human to complete the overwrite through Draw's native save dialog; never fall back to blind replacement.
- Define and test limits for path length, body size, asset byte count, decompressed image dimensions, and allowed media formats. Do not render remote URLs on reopen. Sanitize SVG or reject it; embedded raster assets are the safe initial image format.
- MCP must never expose browser storage, credentials, local unrelated files, or arbitrary network fetch as part of canvas text interpretation.

### Local bridge threat model

- **Current V1 boundary:** the dev bridge binds to loopback, validates an allowlisted loopback Host/port, rejects a mismatched Origin when an Origin header is present, and checks JSON on mutations. The stdio client's local `fetch` omits Origin, so absence is currently accepted. These checks reduce remote-browser/DNS-rebinding exposure; they are not authentication.
- **Threat:** any other local process that can connect to loopback can omit Origin and spoof Host/Origin headers. This applies not only to bridge HTTP tools, but also to editor-side routes/events for client registration, document sync, command acknowledgement, and flush acknowledgement. A tab `clientId` is routing state, not proof of identity; browser origin checks alone do not authenticate local processes.
- **Pairing bootstrap:** pairing can start only from an authenticated editor tab after the human opens Draw's MCP settings and takes a visible start-pairing action. The trusted local Draw runtime mints a random, one-use launch nonce with a short expiry (proposal: 60 seconds) and passes it only in a first-party browser launch URL fragment. The fragment is never sent in an HTTP request; the launched tab exchanges it once over its authenticated app channel for a per-tab secret, and the runtime consumes the nonce. No loopback endpoint returns a launch nonce or issues an editor secret to arbitrary callers. This editor-tab identity is bound to the launched Draw app/tab session and is separate from the paired MCP `clientIdentity`.
- To pair MCP after tab bootstrap, Draw displays a short-lived, single-use pairing code (proposal: 2 minutes) for the authenticated tab. Allow at most 5 failed attempts, then lock pairing for 15 minutes. The lockout survives browser reloads, new pairing sessions, and runtime restarts; starting a session cannot reset the failed-attempt counter. After lockout expires, the human may begin a new pairing session. The trusted MCP process exchanges the code over the protected app channel, and Draw shows its client name/fingerprint for human approval before issuing stable MCP `clientIdentity` and a scoped capability. The pairing code is not a document-access token. Persist the resulting MCP secret in the OS credential store or permission-restricted config; never place secrets in argv, prompts, canvas text, logs, or ordinary tool results.
- **V2 installed runtime:** require the paired capability on MCP bridge routes and the per-tab secret on editor-side registration/sync/ack routes. The tab secret is issued only by consuming the one-time launch nonce and is bound to that launched editor session, paired Draw app, and active editor lease; never expose it to arbitrary loopback callers. Do not authorize using `clientId` alone. Only the active editor lease may sync the document or receive/ack commands. A new tab takeover atomically revokes the old tab secret/lease and invalidates pending command/flush acknowledgements. Require one-time command/flush nonces bound to the active lease, document ID, and revision; reject stale or replayed acknowledgements. Revoking the paired MCP identity also invalidates its editor lease. Scope MCP tokens to a paired `clientIdentity` and allowed tool operations; pass them to the stdio server over protected inherited environment/IPC.
- **Revocation and replay:** revocation immediately blocks new reads/mutations and all mutation replays from that identity, invalidates active editor leases and pending commands/flushes, and rejects late acknowledgements. An operation already applied remains in the document and human-visible history; revocation does not roll it back. The seven-day operation ledger remains available only to the human in Draw for diagnosis; a revoked client cannot query or replay it. Re-pairing creates a new identity and does not inherit old idempotency keys.
- **Limit:** this is local-app protection against unpaired local clients and remote web origins, not a sandbox against a fully compromised operating-system user or process that can read Draw's local credential store/config. State that boundary in the security documentation.
- **Tests:** verify correct/incorrect/missing tokens, revoked identity, loopback/non-loopback, allowed/forged Host, same/mismatched/missing Origin, mutation content type, and body-size limits. Pairing tests prove the launch nonce is passed only in the browser fragment, never sent in HTTP or returned to arbitrary loopback requests, exchanged once for a per-tab secret, and bound to its launched tab/session; an unauthorized loopback process cannot obtain/register a secret. Enforce launch nonce and pairing-code expiry, one-use behavior, five-attempt limit, and 15-minute lockout; prove reload, new pairing session, and runtime restart cannot reset lockout. Also prove an unpaired local process cannot register/take over an editor, sync a document, or send command/flush acknowledgements even when it forges Host/Origin; valid active-tab requests succeed; takeover/revocation invalidates old tab credentials and rejects pending/stale acknowledgements. Persistence tests distinguish in-memory same-process retry from durable replay after restart, and verify `OUTCOME_UNKNOWN` with `reason: process_restarted` plus explicit reconciliation when an applied mutation lacks a durable operation record. Preserve no-Origin stdio only with a valid paired token.

Canvas text and labels are **untrusted data**, whether authored by the human or supplied by an agent. Return them as data fields, never as executable markup or instructions. Do not evaluate HTML/SVG/URLs or follow instructions found inside a label; when an agent consumes text from the canvas, it should treat that text as user content rather than as a system/developer instruction.

## `.draw` compatibility proposal

V1 uses a versioned JSON `.draw` format (`format: "draw"`, `formatVersion: 1`) containing document identity/title, infinite canvas background and viewport, native editor elements, app state, and assets. V2 MCP must operate on the same document model as the UI and persist both `documentRevision` and `viewRevision` in an appropriately versioned form.

- MCP-authored documents validate as normal Draw documents and reopen in Draw.
- Preserve native element fields, text/container and arrow bindings, asset bytes/references and attribution, app state, background, viewport, and stable IDs.
- Never save only a raster image or simplified diagram representation in `.draw`. PNG/JPEG remain separate flattened exports.
- Keep V1 files readable. If revision or workspace metadata requires a new format version, provide a tested migration; preserve compatible unknown element metadata and never silently drop unsupported content.

## Contract tests and validation matrix

Add schema tests and real MCP/Chrome integration tests with each implementation issue. Tests must map to the capability/follow-up rows above:

1. **#31 contract:** reject unknown fields/IDs, invalid geometry/styles, disallowed paths, stale revisions, mismatched extensions, oversized decoded raw bytes and encoded envelopes, duplicate idempotency keys; same key/same payload replays the original result for 7 days, while same key/different payload conflicts; expired keys yield `OUTCOME_UNKNOWN` with `reason: idempotency_expired`; verify durable `clientIdentity` across reload/server restart, viewport gesture coalescing and viewport-only `viewRevision` increments, launch nonce/tab secret binding, pairing/revocation, Host/Origin/body/token checks, editor registration/sync/ack authorization and takeover, and scene-page snapshot invalidation.
2. **#32 authoring:** actual MCP calls create each supported native element, labels/bindings, and no image elements; return stable ID mappings; a human can select and edit those elements in Chrome. Online provider search/download/insertion is excluded here and belongs to #35.
3. **#33 editing/lifecycle:** cover edits, selection, group/ungroup/arrange/delete, undo/redo attribution and conflicts; save as `.draw`, reload, reopen, export PNG/JPEG separately, verify assets/background/viewport/editability; prove an agent undo cannot revert a later human edit; exercise confirmation-token approved/denied/expired/stale results and race-safe new-file collision handling.
4. **#34 workspaces:** migrate a V1 document; create/switch/reload workspaces/canvases without cross-document autosave writes; confirm destructive delete.
5. **#35 external assets:** provider attribution/license persistence, download limits/type checks, embed and save/reopen, and selected-result insertion through both MCP and the browser picker flow.
6. **Failure recovery:** delay acknowledgements past current timeout boundaries; verify same-process read-after-timeout uses the in-memory journal, atomically committed document+ledger entries support replay after restart, and applied-but-unpersisted edits yield `OUTCOME_UNKNOWN` with `reason: process_restarted` after restart. Require read/reconciliation and a new key before another mutation; verify expired durable records yield `reason: idempotency_expired`. Do not assert that a process-only journal survives a restart.

Chrome E2E is required for editor, open/save, and export flows. Unit tests alone do not establish that Draw can render/edit the resulting scene or that round trips preserve it.

## Product and implementation decisions (all proposals pending review)

- **Coverage meaning:** expose semantic document and scene capabilities, not every cosmetic preference or low-level pointer gesture.
- **Active context:** current tools act on the active canvas. V2 document/workspace operations should require an explicit document/workspace ID; they must not silently change active context. `open_document` replacement of dirty content returns `NEEDS_CONFIRMATION`; creating/switching to another saved canvas preserves the prior canvas.
- **Undo ownership:** the agent can undo only its own latest eligible operation; later human/other-client work blocks that undo. The human's ordinary Undo can reverse the latest transaction, including an agent's.
- **Filesystem:** MCP resource/artifact is default for `.draw` and image output; direct read/write is optional only under the explicitly configured Draw root. New files are permitted there; existing-file replacement always requires the app UI confirmation described above.
- **Payload limits:** `.draw` total cap is 100 MiB decoded raw bytes; inline arguments cap at 1 MiB decoded raw bytes; ordered chunks cap at 1 MiB decoded raw bytes each; encoded chunk envelope caps at 2 MiB and complete command envelope at 4 MiB. Use artifacts/resources for large files and keep them out of model context.
- **Assets:** #35 owns all image search and insertion, including online search, local/imported images, review/selection, download, validation, embedding, and attribution. #32 has no image support unless a later issue defines an embedded, validated-asset flow. Embed chosen media for offline reopening and retain source/creator/license metadata. Review each provider's usage terms and per-item license rather than treating an index result as a legal guarantee.
